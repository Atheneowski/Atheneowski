# 📌 Retrospective Frameworks for Teams

## 🚀 Introduction
Retrospectives are a crucial part of continuous improvement for teams, helping to reflect on past work, identify areas for growth, and set actionable goals. Below are structured retrospective frameworks to guide your team through meaningful discussions and drive impactful change.

---

## 🛠 How to Use These Frameworks
- **Preparation**: Share the selected framework with your team in advance and gather feedback asynchronously.
- **Facilitation**: Use a tool like **Figma, Miro, or GitHub Discussions** to capture insights.
- **Follow-up**: Document key takeaways and track action items via **GitHub Issues or a project board**.

## 📝 Collecting Feedback & Follow-Up
- **Pre-Retro Feedback**: Gather insights asynchronously via **Slack or GitHub Discussions**, especially for those who can’t attend.
- **Continuous Feedback**: Request input throughout the project lifecycle, not just at the end.
- **Tracking Outcomes**:
  - **GitHub Discussions**: Summarize key takeaways and action items.
  - **GitHub Project Boards**: Track ongoing improvements and ownership.

[🔗 Learn how GitHub runs inclusive retrospectives](https://github.blog/engineering/engineering-principles/how-we-work-inclusive-retrospectives-for-the-github-accessibility-leadership-team/)

## 🌍 Accessible Retrospectives
If the retrospective needs to be **accessible**, consider implementing:
- **Alternative formats**: Provide text-based options for visually impaired team members.
- **Asynchronous participation**: Use GitHub Discussions or Slack to collect input ahead of time.
- **Clear and structured facilitation**: Ensure all team members feel comfortable participating.

More details on **accessible retrospectives**: [GitHub Engineering Blog](https://github.blog/engineering/engineering-principles/how-we-work-inclusive-retrospectives-for-the-github-accessibility-leadership-team/).
